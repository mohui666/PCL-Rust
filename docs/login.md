## 接入方式

启动器使用自有公共客户端注册，支持个人 Microsoft 账号；不嵌入客户端密码或上游私有凭据。Minecraft API 访问资格需单独审批；本次审批状态来自用户确认。新配置、缺失 ID 或旧配置中的空 ID 自动使用上述默认值，已有非空自定义 ID 保留。

当前实现使用 Microsoft OAuth 设备授权流程，请求 `XboxLive.signin offline_access`。用户自行在 Microsoft 网页中输入设备码并完成授权，启动器不收集 Microsoft 密码。设备码窗口提供打开网页、复制代码和取消操作；Enter 不自动打开网页。

登录按以下顺序进行：

1. 获取设备码，等待用户授权，并处理等待、降低轮询频率、过期和取消。
2. 获取 Microsoft 令牌，依次进行 Xbox Live 和 XSTS 验证。
3. 向 Minecraft Services 交换会话。
4. 检查 Java Edition 权益与玩家资料。
5. 保存必要的刷新凭据和非秘密账号信息，再将账号标记为可用。

“网页登录成功”表示设备授权完成。最终账号状态需等待 Minecraft 权益、资料及保存步骤完成。

## 账号保存与恢复

实现支持多个账号、选择账号、恢复有效会话、刷新及移除已保存账号。磁盘账号清单只保存非秘密元数据；Microsoft 刷新凭据使用 macOS Keychain 或 Windows Credential Manager，Minecraft 访问会话保留在内存中，不写入普通配置文件。

刷新令牌轮换后，先保存新刷新凭据，再继续后续服务交换，避免后续取消或网络失败丢失已经轮换的令牌。保存失败会明确返回错误，不显示为账号保存成功。移除账号会处理其系统凭据条目；切换为离线登录只清除当前账号选择和内存会话，保留已保存账号、离线设置及存档。

确认刷新凭据失效时，界面最多自动进入一次设备重新认证。网络错误、安全存储错误、应用配置错误或 Minecraft HTTP 403 不会被当作凭据失效反复重新授权，也不会静默转为离线账号。旧请求、取消后的迟到事件和新请求分别处理。

原账号发起的启动或外观修改会绑定该账号。若重新认证后登录的是另一账号，新的登录结果可以保留，但原账号待执行的操作会停止，避免误用另一个账号继续执行。

## 皮肤、披风与错误恢复

官方资料中的 `http://textures.minecraft.net/texture/...` 地址在验证主机、路径等边界后统一升级为 HTTPS 下载。皮肤头像与帽子层使用最近邻采样，账号名居中；皮肤和信息菜单使用等宽、左对齐条目。

皮肤操作遇到明确的会话失效响应时，先尝试强制刷新，再在限定次数内继续原操作；必要的设备重新认证仍须用户自行完成。网络失败不会被假定为令牌过期。远端修改已经提交后，即使后续读取玩家资料失败，也不会自动重复提交修改。

披风窗口按当前状态初始化单选项，包含“无披风”和原版 29 个中文别名；未知名称保留服务返回的名称。点击选项仅暂选，用户按“确定”才发起修改，“取消”丢弃暂选。皮肤和披风操作分别报告真实成功或失败。

登录提示区分设备码过期/拒绝、Xbox 资料与家庭权限、权益或玩家资料缺失、网络、限流、服务异常和应用访问拒绝等情况。取消不会显示成认证失败。HTTP 403 保留资格、配置或访问限制等可能原因；TLS 校验保持启用。

## 离线登录与启动

桌面端支持“正版 / 离线”切换。没有选中已保存正版账号时默认显示离线名称；选中过的正版账号仍按原流程恢复。离线用户名、历史记录，以及默认、Steve、Alex、正版名称和自定义 PNG 皮肤设置均可使用，UUID 生成沿用原实现。

CLI 的 `launch`、`plan` 和 `export-script` 支持 `--name 玩家名`；不传 `--account` 时使用离线名称，省略 `--name` 则使用已保存名称。指定 `--account` 时仍须恢复已保存的正版账号，认证失败不会转为离线身份。离线模式不会申请 Microsoft/Minecraft 服务令牌。

实例的 `any`、`microsoft`、`offline` 登录要求仍生效：仅正版实例拒绝离线身份，仅离线实例拒绝正版身份。共享核心仍拒绝无效玩家身份及空令牌/占位令牌的正版会话。

下载、安装游戏文件、Java、加载器、Mod 与整合包管理不要求先登录。历史发行包和此前测试记录不代表本次源码与本机新包的行为。
